# 按问题组织数学建模

Codex 和 Claude Code 共用 [建模任务提示词](../.claude/workflows/mathodology-award-submission.md)。
它是任务简报，不是固定步骤。[比赛侧重点](../.claude/workflows/mathodology-contest-variants.md)
根据实际题目与规则调整，不沿用往年的页数、时间或 AI 政策。

## 围绕四个问题工作

| 问题 | 对应工作 |
|---|---|
| 答案要支持什么决策？ | 阅读题目、数据和当前规则，只澄清会影响解法的缺失约束。 |
| 最简单的有用模型是什么？ | 定义变量、单位、机制、目标和约束，解释为何值得增加复杂度。 |
| 什么会改变结论？ | 比较公平基线，检查误差与可行性，检验关键假设和不利情景。 |
| 读者如何看清证据？ | 选择有用图表，解释结果和不确定性，保留可追踪的计算。 |

依据新证据随时回到相关问题。需要时用简短文字记录假设和选择，没有固定
文件或交接格式。宿主支持时可让专业角色处理有边界的问题，并共享必要上下文、
image2 回答和文件所有权。小任务可由一个 agent 完成。

## 图表工作

使用 [图表预设技能](../.claude/skills/mathodology-figure-presets/SKILL.md)，从问题和数据
出发选择预设，改写绘图与图注提示词。参考素材和合成样张是教学材料，不是本题
证据。图中的单位、估计量、区间和结论必须来自实际计算。

首次设计图表时询问是否有 image2，以及通过工具、已配置接口还是手动使用。
本任务已有回答则沿用；等待时继续分析与数值绘图。有真实入口才调用，否则
交付手动提示词或继续常规绘图。不新建接入框架、不索取聊天密钥、不把通用
图像工具冒称 image2。image2 可辅助配图、机制图和版式；数值层由数据驱动。

无 image2、尚未回答或只能手动使用时，默认运行 [绘图代码模板](../.claude/skills/mathodology-figure-presets/templates/README.md)，传入本题数据生成 PNG/PDF。根据真实数据调整代码，不只交付待执行提示词。

## 审阅与交付

使用 [审稿问题](../.claude/skills/mathodology-award-gates/SKILL.md) 检查论证，不预测奖项。
核对论文方法与代码、核心结论与证据，并按论文尺寸检查密集图表。检查真正
编译的页面；可选 PDF 总览工具帮助发现排版问题，但不能代替细看。修复实质
错误，并清楚说明不确定性。

按请求交付论文、图表、代码或计算说明、已核实引用和复现步骤，遵守本次比赛
的匿名、页数和 AI 使用要求。已有成果可以直接继续，不需要补建阶段日志。
